# Ruleset v1 — the standard competition format

**Status:** proposed — awaiting David's ratification. Nothing depends on this
format until it is ratified.
**Date:** 2026-07-04
**Author:** coder dispatch `M-foedus-ruleset-v1`
**Evidence:** `docs/design/2026-07-04-ruleset-v1-evidence/` (raw `results.json`
+ three figures) — reproduce with `scripts/foedus_ruleset_eval.py`.
**Preset:** `foedus.presets.ruleset_v1` (this PR).

---

## 0. TL;DR — the proposed format

Foedus is becoming a public arena + training gym. Every future experiment and
match should run in **one** standard format so results accumulate on a single
ladder. This doc designs that format and validates the *board* parameters
empirically with cheap heuristic sweeps (no LLM spend).

| Knob | v1 value | One-line justification (evidence §) |
|---|---|---|
| **Seats** | **4** | Best on *every* discrimination metric and lowest elimination-variance on the standard map; simplest coalition math (§6.2). |
| **Turns** | **12** | Discrimination is turn-invariant (§6.3) — so turns is chosen on game-design + cost, *not* discrimination. 12 gives the détente/alliance track a 5-turn window vs 2 at 8 turns, at the point where competitive-band discrimination saturates; 15 only adds cost + elimination. **Most uncertain knob — flag for LLM-layer validation.** |
| **Map radius** | **2** (19-cell disk) | Decisive: radius 2 recovers the true skill ladder (recovery τ ≈ 0.95); radius 1 (7-cell disk) is elimination-dominated and cannot (τ ≈ 0.1–0.36) (§6.1). |
| **Archetype** | **continental_sweep** | Dense connectivity; scarcity (not chokepoints) drives contact — the playtest/conflict-preset choice. |
| **Détente threshold** | **engine default `min(4 + num_players, max_turns − 1)`** (= 8 at 4 seats / 12 turns) | Unchanged. Live at every length (the engine clamps it below `max_turns`); scales with table size; heuristic sweeps show it is neither trivial nor forced (§6.4, §7.3). |
| **Reciprocation ledger** | **ON** | Entrant baseline scaffold (PR #36); engine default. |
| **Campaign memory** | **ON** | Recurring opponents are the point of a ladder (PR #38). |
| **Retreats** | **OFF** | v1 lethality (retreats-evidence packet default). |
| **LLM decision timeout** | **300 s / decision** | The `FOEDUS_LLM_CLI_TIMEOUT` client default (PR #38) — a client setting, not a board field (§7.3). |
| **Games per match** | **8** (two 4-seat rotation cycles) | A match is a *provisional* read; the **persistent** cross-match ladder does the heavy convergence (§6.5, §7.6). |
| **Seat rotation** | **cyclic Latin square** over the 4 seats | Each entrant occupies each seat position equally often (§7.4). |
| **Seeds** | **commit-reveal** (SHA-256 committed before, revealed after) | Anti-cheat for a public arena (§7.5). |
| **Roster** | **4 entrants**, or **3 entrants + 1 house anchor** | House anchor = fixed-skill calibration seat that ties the global ladder together (§7.7). |
| **Rating** | **OpenSkill (Plackett-Luce), per game**, **unique identity per entrant** | Conservative `μ − 3σ` standings (§7.8). |

**Per-entrant cost of one match:** ~8 games × ~48–72 LLM decisions/game ≈
**~380–580 calls ≈ ~6–10 h sequential** at ~1 min/decision (§7.9).

## 1. Purpose and scope

**In scope (this doc decides):** the board parameters (seats / turns / radius /
archetype), the standard toggles, the match structure (games-per-match, seat
rotation, sealed seeds), roster composition, and the rating protocol — plus the
empirical evidence for the parameters that could be measured cheaply.

**Explicitly out of scope:** the leaderboard/web productization, a matchmaking
service, entrant-onboarding docs, the rating-identity and resolver fixes owned
by a parallel coder (`foedus/rating.py` and `foedus/resolve.py` are untouched
here), and any large LLM-seat experiment. This design *assumes* unique rating
identities (the duplicate-identity fix lands separately).

**Method in one sentence:** run a fixed heuristic skill ladder through every
candidate format with the cheap sim harness (no LLM calls) and let
pre-registered metrics pick the parameters.

## 2. The skill ladder (calibration, reproducible)

Discrimination can only be *measured* against a field of known, graduated skill.
A **reproducible** 4000-game calibration (harness phase 0; `results.json →
calibration`) rates twelve candidate heuristics at the base format
(4 seats / 12 turns / radius 2) and reports OpenSkill μ/σ **plus two
OpenSkill-independent signals** — mean placement and win-rate — so the ordering
is not a single-metric artifact:

| Heuristic | μ | mean rank | win-rate | in ladder |
|---|---|---|---|---|
| DishonestCooperator | 37.08 | 1.629 | 54.7% | ✓ (rung 6, required) |
| Bandwagon | 36.60 | 1.718 | 47.4% | — (tied top cluster) |
| GreedyHold | 36.14 | 1.710 | 47.1% | — (tied top cluster) |
| TitForTat | 35.82 | 1.711 | 50.0% | — (tied top cluster) |
| Aggressive | 28.04 | 2.124 | 28.5% | ✓ (rung 5) |
| OpportunisticBetrayer | 26.19 | 2.299 | 20.0% | — |
| Greedy | 25.15 | 2.479 | 13.6% | ✓ (rung 4) |
| Sycophant | 23.53 | 2.493 | 13.7% | ✓ (rung 3) |
| AntiLeader | 19.72 | 2.718 | 8.9% | — |
| Random | 19.67 | 2.878 | 7.1% | ✓ (rung 2) |
| ConservativeBuilder | 7.01 | 3.310 | 0.0% | — |
| Defensive | 6.83 | 3.316 | 0.0% | ✓ (rung 1, floor) |

The three metrics agree on the ordering (μ, mean-rank, and win-rate are
monotone together), so the ladder is a real skill gradient, not an OpenSkill
quirk. The **six-rung LADDER** takes one rung from the statistically-tied top
cluster (Bandwagon / GreedyHold / TitForTat / DishonestCooperator all emit
GreedyHold orders — μ within 1.3) — namely the required freerider probe
**DishonestCooperator** — so no two rungs are a tie by construction. Spacing at
the base format (weak→strong μ gaps): Defensive→Random **12.8**, Random→Sycophant
**3.9**, Sycophant→Greedy **1.6** (the deliberate near-tie), Greedy→Aggressive
**2.9**, Aggressive→DishonestCooperator **9.0** — wide ends, a tight middle. The
wide gaps test that a format separates *obvious* skill; the tight
Sycophant↔Greedy pair tests how much data it takes to separate *close* skill —
which turns out to be the crux of games-per-match (§6.5). Defined in
`foedus/eval/ruleset.py:LADDER`; regenerate with `--phases 0`.

## 3. Pre-registered metrics and selection criteria

The metrics were encoded in `foedus/eval/ruleset.py` and committed **before** the
grid was run (git: harness commit precedes the evidence commit). The numbers, not
taste, pick the format. Every grid cell is run over **5 independent seed
batches** so the metrics carry a real spread, not a single point estimate.

- **Recovery fidelity τ** — Kendall τ between a format's asymptotic OpenSkill
  ordering and the true ladder. A format is *valid* only if **τ ≥ 0.9**. **This
  is the gate**, and it must be read *before* any discrimination number.
- **Full discrimination D_full** = `stdev(μ) / mean(σ)` across all six rungs.
  Caveat (learned in review): D_full is **tail-dominated** — the floor↔ceiling
  spread swamps it, so every valid format scores high and D_full is nearly blind
  to the competitive middle. It is reported but not decisive.
- **Competitive-band discrimination D_mid** = the same index over the four
  *middle* rungs (`MID_LADDER`, floor and ceiling dropped). This is the metric
  that reflects separating *close* skill.
- **Tightest adjacent gap** (`min_adjacent_separation`) — the hardest single
  pair to tell apart, in combined-σ units; the bottleneck D hides.
- **Convergence** — two statistics on the match standings: **g_tau90** (first
  game count whose *mean* τ stays ≥ 0.9 — smooth, robust) and **g95** (first
  count that stays ≥ 95 % *perfectly* sorted — strict and noisy near threshold).
- **Health guards** — détente rate (a coordination, not skill, signal if high)
  and elimination rate (variance that drowns skill if extreme).

**Cost lenses.** Seats: metrics **per game**. Turns: **per turn** (an LLM entrant
pays ~1 min per decision, ~1 decision per turn). Radius: per game, noting its
marginal effect on prompt size.

**Decision rule (pre-registered):** gate on τ ≥ 0.9; among valid formats, prefer
the seats × radius with the best competitive-band discrimination per unit cost;
choose the turn length on cost + game-integrity once discrimination is shown
turn-invariant.

## 4. Method

`scripts/foedus_ruleset_eval.py` reuses the engine's `run_one_game` (no game
logic is duplicated; `rating.py`/`resolve.py` untouched) across four phases:

0. **Calibration** — the 12-candidate ladder selection (§2), reproducible.
1. **Format grid** — seats {4,5,6} × turns {8,12,15} × radius {1,2} = 18
   formats, **5 seeds × 2000 games each**, distinct-seat sampling of the ladder.
   Per format: D_full, D_mid, tightest gap, recovery τ, détente/elim/length, all
   as mean ± std over seeds.
2. **Convergence** — for representative match rosters, replay 800 games in 400
   shuffled orders and record P(standings sorted) and mean τ vs games.
3. **Détente sensitivity** — an ALLY-inclined roster across turn lengths, to
   separate the format's effect on détente from the (dominant) roster effect.

**Distinct-seat sampling** is the one methodological choice worth flagging: a
real match seats *distinct* entrants, so every seat carries a unique rating
identity. The stock sweep draws seats i.i.d. *with replacement* (two seats can be
the same heuristic → duplicate identities in one game — the exact case the
parallel rating-identity fix owns). Sampling without replacement models the
format we are actually designing and keeps this work off the duplicate-identity
path. Détente runs at the **engine-default** threshold (not disabled) so détente
rate is a real measurement.

All runs: `continental_sweep`, no LLM calls, deterministic. Full run ≈ **5 min**
on 12 cores (`results.json → elapsed_secs` = 309 s).

## 6. What the evidence says

### 6.1 Map radius — decisive (radius 2)

This is the clearest result in the study. **Every radius-2 format at 4–5 seats
recovers the ladder (τ ≈ 0.95–0.97); no radius-1 format does** — radius-1 τ is
+0.36 / +0.25 / **+0.09** (4/5/6 seats), i.e. barely better than a random
ordering. Radius 1 is a 7-cell hex disk (~6–7 playable nodes); with 4–6 home
bases packed into it, games are elimination brawls (elim 30–46 %) whose outcome
is dominated by starting adjacency, not skill. Note the trap the τ gate catches:
radius-1's D_full at 6 seats (2.26) *looks* nonzero, but it is the spread of a
**scrambled** ordering (τ = 0.09) — meaningless as discrimination. **Radius 2 is
required.**

On circularity: the ladder ordering was calibrated at the base format (4/12/2),
so τ = 0.95 there is partly a self-consistency check, not fully independent
validation. But (a) the ladder is corroborated by two OpenSkill-independent
metrics (§2: mean-rank and win-rate agree), and (b) the radius *decision* is
robust to the choice of ground truth — a radius-1 elimination brawl scrambles
*any* graduated skill order, which is exactly what τ ≈ 0.1 measures. (A radius-3
board — the engine default, ~37 cells — was outside the brief's 1-vs-2 scope; §9
flags it for the larger-table follow-up.)

### 6.2 Seats — 4

Among the τ-valid (radius-2) formats, **4 seats wins on every discrimination
metric**: D_full 4.85 (vs 3.92 / 3.42 at 5/6 seats), **D_mid 1.91 ± 0.13**
(vs 1.40 / 1.09 — a gap well beyond the seed spread), and the widest tightest-gap
(0.33 vs 0.27 / 0.15), all at 12 turns. It is also the healthiest: **elimination
roughly doubles per two seats** (10 % → 19 % → 32 % at 12 turns), and 6 seats at
radius 2 actually slips under the τ gate (0.81) — crowding on a fixed 19-cell
board turns games into elimination lotteries.

A confound worth stating (and it runs *for* this conclusion): with distinct-seat
sampling from a six-rung ladder, each identity plays more games at higher seat
counts (6/6 vs 4/6 of the batch), which should *lower* its σ and *raise* D — yet
D falls with seats anyway (mean σ 1.72 at 4 seats vs 1.83 at 6). So the crowding
penalty is even stronger than the raw numbers suggest. Four seats also keeps the
freerider/coalition social layer legible (2-v-2 vs 3-v-1 is the richest structure
still analyzable). **4 seats.** (If a future format wants 5–6 seats for social
richness, §6.1's radius-3 follow-up should come first so the board isn't the
bottleneck.)

### 6.3 Turns — 12 (discrimination is turn-invariant; the choice is game-design + cost)

**Discrimination does not distinguish the turn lengths.** At 4 seats / radius 2:
D_full is flat (4.84 / 4.85 / 4.78 at 8/12/15, within noise); recovery τ is
≥ 0.95 at every length; the tightest gap is flat (0.26 / 0.33 / 0.30).
Competitive-band D_mid trends mildly upward (1.73 / 1.91 / 2.05) and **saturates
by 12** — the 8→12 rise is at the edge of significance with 5 seeds, and 12→15
adds nothing distinguishable. The only monotone format effect is **elimination
rising** with turns (4 % → 10 % → 14 %). So on the brief's discrimination-per-turn
lens, more turns buy essentially no skill signal.

That is *liberating*, not a dead end: because discrimination is turn-invariant,
the turn length can be set on **game-design grounds without compromising the
skill measurement.** Two design pulls:

- **Cost** favors fewer turns (entrant cost ∝ turns). On cost alone, 8 wins.
- **Game integrity** favors enough turns for the détente/alliance track — the
  condition that names the project (*foedus* = treaty) — to be a live strategic
  option, not a last-second accident. The engine clamps the détente threshold to
  `min(4 + num_players, max_turns − 1)`, so it is *always* reachable, but the
  *window* matters: at **8 turns** the threshold is **7** → a 2-turn window
  (turns 7–8); at **12 turns** it is 8 → a comfortable **5-turn window** (turns
  8–12); at 15, an 8-turn window. A 5-turn window lets an entrant commit to peace
  mid-game and still get there; a 2-turn window barely does.

**12 turns** is the choice: it sits at the competitive-band saturation point,
gives the alliance track a real window, and stops short of 15's extra cost and
elimination for no discrimination gain.

> **Honest caveat — this is the most uncertain knob.** "Turns don't add skill
> signal" is a *heuristic-layer* result; heuristics don't negotiate, so their
> skill is largely a turn-1 property. For LLM entrants, mid-game negotiation,
> betrayal timing, and the détente race may make later turns genuinely
> informative — which the heuristic sweep *cannot* see. 12 is the conservative
> middle that protects that possibility; an operator minimizing cost could
> justifiably run 8 (détente still fires, just in a tighter window). This is the
> parameter to validate with an LLM turn-length A/B before v2 (§9).

### 6.4 Détente and elimination by format

**Détente is a roster phenomenon, not a format one.** Across the *entire*
18-format grid the skill ladder produced détente **exactly 0.0 %** — the rungs
don't coordinate all-pairs-ALLY. Swap in an ALLY-inclined roster (Cooperator /
TrustfulCooperator / DishonestCooperator / Sycophant) and détente fires **66–82 %**.
So détente rate measures *how cooperative the field is*, and the format only
nudges it. The rate is even **non-monotonic in turns** — 70 % / 66 % / 82 % at
8 / 12 / 15 — which the threshold clamp explains: 8 turns has the *lowest* bar
(threshold 7) so it fires easily; 12 and 15 share threshold 8, and 15 wins on
sheer headroom to accumulate the streak. This directly disproves any "8 turns
makes détente degenerate" intuition: 8 turns fires détente *more* often than 12,
not less. **Implication:** détente-threshold tuning is an *LLM-layer* question
(the C2 reciprocity-sweep note of 10.34 % détente sits between these poles — a
field that is *sometimes* cooperative); the heuristic sweeps show the default is
neither trivially reachable nor impossible, so v1 keeps it (§7.3).

**Elimination** *is* format-sensitive and behaves sensibly: it rises with seats
(crowding) and turns (more chances), and explodes at radius 1. At the recommended
4/12/2 it is a moderate 9.9 %, and games run the full 12 turns (mean length 12.0)
— decided by supply score, not a first-strike lottery, which is what we want.

### 6.5 Rating convergence — "games per match" is about field *separation*, and the persistent ladder

See `fig1_convergence.png`. Modelling a match as a fixed set of recurring
entrants with seat rotation, replayed in 400 shuffled orders:

| Match field | g_tau90 (mean τ ≥ 0.9) | g95 (perfectly sorted) | mean τ @ 800 |
|---|---|---|---|
| 4 entrants, well-spread | **10** | 60 | +1.00 |
| 4 entrants, **incl. a near-tied pair** | > 800 | > 800 (0.59 @ 800) | +0.86 |
| 5 entrants, well-spread | 60 | 800 | +0.99 |
| 6 entrants, full ladder (near-ties) | > 800 | > 800 (0.32 @ 800) | +0.86 |

Two honest readings:

- **Both field separation and seat count matter, and separation matters more.**
  A well-spread 4-field sorts its *whole* order by ~10 games (mean τ ≥ 0.9). Add
  one near-tied pair and even 4 entrants never fully sort in 800 games (0.59) —
  worse than a well-spread 5-field (0.97) though still better than the 6-field
  (0.32). So a genuine coin-flip pair (Greedy↔Sycophant, ~1.6 μ) is the dominant
  bottleneck, with each extra seat adding pairs to get right on top. **Note g95
  is a strict, noisy first-crossing statistic** (a single discordant pair drops
  τ below 0.9 at these roster sizes, and with 400 shuffles the ±SE near threshold
  is ~1 pp) — read g_tau90, and the mean-τ column, as the robust signals.

- **A single match cannot be sized to fully converge affordably, so the
  persistent ladder does it.** g_tau90 = 10 is the *easy* case; realistic close
  fields want far more, and even 60 games × ~60 calls ≈ a day of LLM time per
  entrant. The answer is the **persistent** unique OpenSkill identity (§7.6,
  §7.8): a match yields a *provisional* read (mean τ ≈ 0.9 by ~10–15 games, σ
  falling from 8.7 → ~4), and ratings keep refining across matches against
  recurring opponents. Turn length barely moves it (4-spread g_tau90 = 10 at both
  8 and 12 turns; g95 60 vs 120).

  > **Caveat (I3).** This curve fixes the *same* entrants for all games. A real
  > arena ties *different* matches together only transitively (or via the house
  > anchor, §7.7), so cross-match convergence is strictly slower and noisier than
  > shown — "8 games/match is enough because the ladder converges over several
  > matches" is well-motivated but rests on the house anchor and recurring
  > pairings, not on a rotating-roster simulation (a §9 follow-up).

## 7. The format, specified

### 7.1 Board
`num_players = 4`, `max_turns = 12`, `map_radius = 2`,
`archetype = continental_sweep`, `build_period` = engine default.
Encoded in `foedus.presets.ruleset_v1`.

### 7.2 Ladder separation at the recommended format
`fig3_ladder.png`; pooled 10 000-game μ ± σ at 4/12/2:

| rung | μ | σ |
|---|---|---|
| DishonestCooperator | 36.80 | 1.76 |
| Aggressive | 30.76 | 1.69 |
| Greedy | 25.19 | 1.66 |
| Sycophant | 23.98 | 1.66 |
| Random | 22.21 | 1.67 |
| Defensive | 9.90 | 1.88 |

Mean 3.2 / 5 adjacent pairs confidently separated (the two that aren't are the
deliberate near-ties Greedy↔Sycophant and Sycophant↔Random). This is a healthy,
legible skill spectrum.

### 7.3 Détente threshold and decision timeout
**Détente threshold:** keep the engine default,
`min(4 + num_players, max_turns − 1)` (= 8 at 4 seats / 12 turns). Justification:
(a) it is *live* at every length by construction (the clamp keeps it below
`max_turns`), and 12 turns gives it a comfortable 5-turn window; (b) it scales
with table size — a bigger table needs more turns of unanimous peace, the right
difficulty curve; (c) the sweeps bracket it as non-degenerate (0 % for a
competitive field, 66–82 % for pure cooperators). No cheap heuristic evidence
justifies moving it; if it moves, that is an LLM-layer decision (§9).

**Decision timeout:** the "300 s" is the per-decision LLM-client timeout
(`FOEDUS_LLM_CLI_TIMEOUT`, PR #38), *not* a `GameConfig` field. Match-level and
client-level settings are layered *around* the engine config, which stays a pure
state-transition core (architecture invariant) — hence they are not fields on the
preset.

### 7.4 Seat rotation
Seat/board asymmetry is real (home adjacency differs by position), so entrants
must cycle through seats. **Scheme:** the four entrants play a **cyclic Latin
square** — over any four consecutive games each occupies each of the four seat
positions exactly once (game *k*: entrant *i* → seat `(i + k) mod 4`). An 8-game
match is two full cycles: perfectly balanced. The map seed varies per game
(§7.5), so entrants also see a spread of boards, not one board four ways.

### 7.5 Sealed seeds (commit-reveal) — anti-cheat for a public arena
Per-game determinism must not let an entrant pre-compute or recognize a board.
1. **Commit (before the match):** draw the seed list `S = [s₁ … s_G]` from a
   CSPRNG, compute
   `commit = SHA-256("foedus-ruleset-v1|" + match_id + "|" + json(S) + "|" + nonce)`,
   and **publish `commit` + `match_id`** *before any game is played*.
2. **Play:** games run on `S` in order with the §7.4 rotation. Entrants never see
   `S` or `nonce`.
3. **Reveal (after the match):** publish `S` and `nonce`; anyone recomputes the
   hash to confirm the seeds were fixed in advance and not cherry-picked.

This binds the operator (can't re-roll a disliked seed) and the entrants (can't
have been shown the seeds). `nonce` blocks brute-forcing `S` from the hash;
`match_id` domain-separates commits. Seeds are the engine's existing
`GameConfig.seed` — no engine change needed.

### 7.6 Games per match — 8, with the ladder doing the convergence
A match is a **campaign** of recurring opponents (PR #38 made cross-game memory a
measured axis). **v1 match = 8 games** = two seat-rotation cycles: perfectly
seat-balanced, and enough that mean τ ≈ 0.9 with σ well down from the prior. A
single match is deliberately *provisional*; §6.5 shows full convergence can't be
bought inside one affordable match, so the **persistent ladder** carries it (with
the rotating-roster caveat of §6.5). A **4-game** (one-cycle) variant is offered
for tight budgets. Do **not** size a match for full single-match convergence —
that is a day-plus of LLM time per entrant (§7.9) for a precision the persistent
ladder reaches over several matches.

### 7.7 Roster composition
**v1 default: 4 entrants**, all four seats filled by the match's four entrants —
the simplest thing that yields comparable ratings. **Calibration variant:
3 entrants + 1 house anchor** — a fixed-skill house agent (e.g. a
DishonestCooperator-class "boss") in one seat. The anchor is the same identity in
every match it appears in, so it ties otherwise-disjoint matches onto a common
scale (like a reference player in an Elo pool) and doubles as a sanity boss.
Recommendation: run the anchor in a fraction of matches so the global ladder stays
commensurable even when entrant pools don't overlap — this is also what makes the
§7.6 persistent-ladder argument hold under rotating rosters.

### 7.8 Rating
OpenSkill (Plackett-Luce) via `foedus.rating.RatingSystem`, updated **once per
game** from the game's competition ranks (`foedus.scoring.compute_match_result`
conventions; ties share a rank, eliminated share the worst). **Unique identity per
entrant** — persistent across every game of every match (this design assumes the
duplicate-identity fix; it does not implement it). Standings use conservative
`μ − 3σ`. Rating consumes only final ranks, so it is identical whether or not
entrants negotiate (press-independent).

### 7.9 Cost envelope
Per entrant, per game, at 4/12/2: ~12 turns × (≈1 negotiation + 1 orders
decision) ≈ **~48–72 paid LLM calls** (the brief's "~48 calls/game today" anchors
the lower end; press-heavy rounds push toward 72). At ~1 min/call:

| Match size | calls / entrant | wall-clock / entrant (sequential) |
|---|---|---|
| **8 games (v1)** | ~380–580 | **~6–10 h** |
| 4 games (budget) | ~190–290 | ~3–5 h |
| 60 games (full single-match convergence — *not recommended*) | ~2.9–4.3 k | ~2 days |

Turns are the dominant multiplier (cost ∝ turns), which is why §6.3 refuses to pay
for 15. Seats add *parallel* seat-cost per game but not per-entrant serial cost.
The persistent ladder (§7.6) is what makes the affordable 8-game match sufficient.

| Turns | 12 | **8** (cheaper, equal discrimination) | ~33 % lower entrant cost | Discrimination is turn-invariant, so 8 and 12 measure skill equally well; 12 buys the détente/alliance track a 5-turn window (vs 2 at 8) and the competitive-band saturation point. The negotiation value of turns is **unmeasured** — a conquest-only, cost-minimizing operator could pick 8. **Most uncertain knob.** |
| Turns | 12 | 15 (marginally higher D_mid) | a hair of competitive-band discrimination | 12→15 D_mid gain is within noise; 15 adds +25 % cost and +40 % elimination for it. |
| Seats | 4 | 5–6 (richer social layer) | more coalition/kingmaker structure | 5–6 seats measurably *lose* discrimination to crowding on radius 2, and 6 seats slips under the τ gate; fix the board (radius 3) before widening the table. |
| Radius | 2 | (radius 1 rejected outright) | — | Radius 1 fails the τ gate (τ ≈ 0.1–0.36); no trade-off, just a wrong answer. Radius 3 is a live follow-up for larger tables. |
| Games/match | 8 | full convergence (~60+) | single-match precision on near-tied fields | ~60 games is a day-plus/entrant; the persistent ladder reaches that precision over several matches — *if* recurring pairings / a house anchor tie matches together (§6.5, §7.7). |
| Détente threshold | default (clamped) | a tuned value | possible LLM-layer optimum | No cheap evidence justifies a specific value; heuristic sweeps only bound it as healthy. Defer to an LLM study. |

## 9. What this pass did **not** settle (follow-ups)

- **Turn length at the LLM layer** — the most uncertain knob (§6.3). Heuristics
  express skill by turn 1; "past turn 8 adds no discrimination" may not hold once
  entrants negotiate. Worth a small LLM turn-length A/B (8 vs 12) before v2. No
  1-game claude-cli smoke was run here because no recommended parameter changes
  prompt structure enough to warrant it (radius 2 vs 3 would; we stayed at 2).
- **Détente-threshold tuning** is inherently an LLM/press-layer question (§6.4).
- **Radius 3 for larger tables** — 5–6 seats lose discrimination to radius-2
  crowding; a radius-3 board may let bigger tables breathe. Outside the 1-vs-2
  brief.
- **Rotating-roster cross-match convergence** (§6.5 caveat) — the games-per-match
  recommendation assumes the persistent ladder converges across matches via
  recurring pairings / the house anchor; a rotating-roster simulation would
  confirm it.
- **The duplicate-identity and resolver fixes** are owned by a parallel coder;
  this design assumes unique identities and does not touch `rating.py` /
  `resolve.py`.

## 12. Amendment — Ruleset v1.1: identity-keyed memory

**Status:** ratified amendment. Discovered while preparing the first canonical
campaign (`M-foedus-canonical-campaign-v1`); **David approved 2026-07-04**.
Implemented in that PR (`foedus/agents/llm/campaign_memory.py`,
`render.py`, `diplomat.py`; `scripts/foedus_canonical_campaign.py`).

**The conflict.** Two v1 requirements collide for LLM seats. §7.4 rotates seats
every game; but the cross-game campaign memory shipped in PR #38 keys opponents
**by seat number**, and its self-note prompt tells each agent *"the next game
reuses the SAME seats, so you will face these same opponents again"*
(`render.py`). Under rotation that sentence is false: a note "seat 2 kept
freeloading" is applied next game to whichever *different* entrant now sits in
seat 2. Seat-keyed memory under rotation is therefore not merely useless — it is
**actively misleading**, and it makes the campaign's headline question (does a
persistent freerider get identified and coordinated against across games?) null
*by construction* while degrading the decision-log training corpus.

**The fix (v1.1).** Each entrant carries a stable, **neutral handle** (e.g. NATO
letters) that does not change when seats rotate — nothing in the handle hints at
a player's strategy (the freerider house anchor gets an equally neutral handle).
Concretely:

- Agents see opponents **by handle** in all social state (public stances,
  reciprocation ledger/standing, inbound intents, visible units, and the
  cross-game record), plus a **per-game seat legend** (`p2 = Foxtrot`) that maps
  this game's seats to handles so the agent can act in the engine's seat space.
- **Campaign memory + self-notes key on the handle**; the self-note prompt is
  reworded to reference handles, not seats. The handles **double as the OpenSkill
  rating identities**, so entrants are rated individually rather than collapsed
  into one `"LLMDiplomat"` identity.
- **Neutrality is unchanged**: the legend and handle-annotated facts are
  harness-computed and pass the same leading-words denylist as the v1 ledger;
  self-notes remain verbatim/exempt (model output).
- The handle→role map (which handle is the freerider) is recorded
  **operator-side only** (`campaign_plan.json`), never shown to agents.

Back-compatible: the mechanism is opt-in via an `IdentityContext`. With none
supplied — the single-game arm and every pre-v1.1 experiment — prompts and facts
are **byte-identical** to the seat-keyed behaviour. Only a rotating campaign
supplies handles. TDD covers the cross-game handle round-trip (a note about an
entrant in game *k* applies to the same entrant in game *k+1* regardless of seat)
and the legend's neutrality.
